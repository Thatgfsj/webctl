# ADR-0004：礼貌与限速是默认姿态，不承诺绕过反爬

- 状态：已采纳（2026-10-16）
- 关联：[ADR-0001](0001-single-layer-builtin.md)、[PLAN §3.8](https://github.com/Thatgfsj/webctl/blob/main/docs/PLAN.md)

## 背景

去掉浏览器后，webctl 的请求与普通 HTTP 客户端无异：没有真实浏览器的行为特征，也没有渲染耗时带来的天然节流。如果默认"能多快就多快"，这个工具会很容易被用来把目标站点打挂，也很容易被封——而"被封"往往会以 `200` + 拦截页的形式出现，被误判为业务数据。

同时必须承认：本项目的定位不是突破反爬，而是给 agent 一个**稳定、诚实、可控**的取回层。

## 决策

**把礼貌与限速做成默认行为，把"被拦截"做成可识别的显式结果。**

1. 默认每主机并发上限 **2**、默认同主机最小请求间隔 **1s**，均可配置。
2. 尊重 `Retry-After`；失败重试有次数与退避上限，不做无限重试。
3. 默认解析并遵守 `robots.txt`；显式关闭时必须在信封里记录"已关闭"这一事实。
4. 识别拦截页（Cloudflare / 验证码特征）→ 返回 `BLOCKED` + 可读诊断，**不重试轰炸**。
5. 只提供合规手段：TLS 指纹（wreq + wreq-util，见 `docs/spikes/wreq.md`）、合理的请求头、限速与退避。**不承诺、也不实现绕过验证码。**

## 备选方案

| 备选 | 为什么不选 |
|---|---|
| 默认不限速，交给调用方自觉 | 默认值就是实际行为的最大公约数；"可选限速"在批量任务里等于没有 |
| 默认忽略 robots.txt | 会把工具变成滥用工具；且有明确的合规风险 |
| 内置验证码识别 / 打码服务 | 越界：与"诚实失败"的产品姿态冲突，也引入外部服务依赖 |
| 遇到拦截静默重试直到成功 | 加剧封锁，且把"被拦截"伪装成网络抖动 |

## 后果

- 批量取回会比"裸并发"慢——这是**有意的**取舍，配置项可以放宽，但默认值必须保守。
- `BLOCKED` 不再只表示 HTTP 4xx/5xx，也覆盖拦截页；文档必须说明"被拦截 ≠ 站点没内容"。
- 测试需要能断言默认限速（并发上限、最小间隔、Retry-After、退避上限），见 TESTING.md 的 POLITE-01…10。
